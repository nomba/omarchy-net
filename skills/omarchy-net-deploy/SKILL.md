# omarchy-net-deploy

Разворачивает сетап из репозитория omarchy-net на новой машине. Репозиторий самодостаточен:
все параметры в `settings.json`, установщики идемпотентны, секреты (SSH-ключи) в репозитории не хранятся.

## Что разворачивается и зачем

- Хост (Windows): SSH-туннель `127.0.0.1:<tunnelPort>` → HTTP-прокси на VDS и sing-box
  (SOCKS `127.0.0.1:<socksPort>`), которым пользуется ТОЛЬКО гость. sing-box хоста направляет
  `ruDomains` напрямую, остальное в туннель. Оба процесса под супервизором `host/omarchy-proxy.ps1`
  (задача планировщика `OmarchyProxy`, автозапуск, авторестарт, лог `host/proxy.log`).
- Гость (Try Omarchy / Arch): sing-box с TUN перехватывает весь трафик в SOCKS хоста;
  nftables разрешает исходящие пакеты ТОЛЬКО на `10.0.2.2:<socksPort>`.

Главное инвариантное условие пользователя: **никакой трафик гостя не должен уходить мимо прокси**,
включая DNS и процессы под sudo. Поэтому никогда не добавляйте в `guest/nftables.conf.tpl`
исключения по UID, прямой DNS (10.0.2.3) или direct-правила «для удобства» — это ломает
ключевое свойство сетапа. Разделение ozon/wb делается только на хосте именно по этой причине.

HAPP и прочие Windows-приложения независимы: не меняйте их настройки и не направляйте их на
порты этого сетапа.

## Предусловия (проверить ДО установки)

1. Windows 10/11 x64; Try Omarchy установлена и запускается.
2. `C:\Windows\System32\OpenSSH\ssh.exe` существует.
3. `ssh <vdsHost из settings.json>` заходит по ключу без пароля. Если нет — настройте ключ
   (`ssh-keygen`, добавить pubkey на VDS) до продолжения, иначе супервизор будет перезапускать
   туннель бесконечно.
4. На VDS доступен HTTP CONNECT-прокси на `127.0.0.1:<vdsProxyPort>`.
5. PowerShell запущен от администратора для host-части.

Если какое-то предусловие не выполняется — сначала восстановите его, не пытайтесь «обойти»
установку.

## Развёртывание

1. Клонировать репозиторий (или найти существующую копию). При необходимости поправить
   `settings.json` (VDS, порты, домены). Версия и SHA256 sing-box уже зашиты — не менять без нужды.
2. Хост: `powershell -ExecutionPolicy Bypass -File host\install-host.ps1` (от администратора).
   Скрипт скачает sing-box, проверит хеш, сгенерирует `host/config.json`, пересоздаст задачу
   `OmarchyProxy` и запустит её.
3. Проверить хост: `curl.exe --socks5 127.0.0.1:<socksPort> https://api.ipify.org` → IP VDS.
   Если таймаут — читать `host/proxy.log` и устранить причину до перехода к гостю.
4. Пробросить репозиторий в гостя: `TryOmarchy.exe -share "<абсолютный путь к репозиторию>"`.
   В госте репозиторий появится в `/mnt/host`.
5. Гость: `cd /mnt/host/guest && bash install-guest.sh` (нужен sudo; пакеты ставятся через pacman,
   поэтому на момент установки у гостя должен быть временный интернет любым способом).
   Установщик также запускает `configure-location.sh`: по `ipinfo.io` проверяет, что выходом
   является именно VDS, выставляет его часовой пояс и сохраняет город/координаты
   через `omarchy-weather-location --set`. Не заменяй это автоопределением `wttr.in`: его GeoIP
   может ошибочно считать VDS российским. После смены VDS повтори `bash configure-location.sh`.
6. Удалить старые per-app настройки, если были: `env = *_PROXY` в конфиге Hyprland,
   `git config --global http.proxy`, `ProxyCommand` в `~/.ssh/config`, `XferCommand` в pacman.conf.

## Временный SSH-доступ к гостю (для команд и диагностики)

Для выполнения команд внутри Omarchy можно включить SSH только на текущую загрузку:

```powershell
& "$env:LOCALAPPDATA\TryOmarchy\TryOmarchy.exe" `
  -start `
  -share "<существующая общая папка>" `
  -ssh 2222 `
  -ssh-key "$HOME\.ssh\id_ed25519.pub"
```

Это запускает гостевой `sshd`, пробрасывает `127.0.0.1:2222` на порт 22 гостя и
авторизует указанный публичный ключ для provisioned-аккаунта Omarchy. Без `-ssh-key`
Try Omarchy сам выбирает стандартный `~/.ssh/id_*.pub`. Подключение с хоста:

```powershell
ssh -p 2222 `
  -i "$HOME\.ssh\id_ed25519" `
  -o IdentitiesOnly=yes `
  -o BatchMode=yes `
  <omarchy-user>@127.0.0.1
```

- Приватный ключ остаётся только на Windows и не копируется в репозиторий или гостя.
- Порт доступен только с loopback; не expose SSH на LAN без отдельного запроса пользователя.
- Это отдельный management-канал QEMU, а не обход прокси для интернет-трафика гостя.
- Если VM уже запущена без SSH, `-ssh` на лету не включается. Перед чистым выключением и
  перезапуском получи разрешение пользователя и сохрани текущую общую папку `-share`.
- SSH-ключ не заменяет локальный sudo: у персонального аккаунта он может требовать пароль
  или Windows Hello. Такие операции выполняй через локальный терминал гостя с участием пользователя.
- После обычного перезапуска без `-ssh 2222` временный доступ исчезает.

## Приёмка (все проверки обязательны)

В госте:
- `curl https://api.ipify.org` → IP VDS.
- `timedatectl` → часовой пояс VDS (NTP/UDP через HTTP CONNECT не проходит).
- `omarchy-weather-location` / `omarchy-weather-status` → город VDS, не ошибочный RU-город.
- `curl -I https://www.ozon.ru` и `https://www.wildberries.ru` → HTTP 200/301 (direct делает хост).
- `ping -c2 8.8.8.8` → 100% потерь; `sudo nc -zv -w3 1.1.1.1 443` → отказ/таймаут.
- Kill switch: `sudo systemctl stop sing-box` → `curl -m 5 https://api.ipify.org` таймаут;
  затем `sudo systemctl start sing-box`.

Если любая проверка не прошла — не объявляйте установку завершённой; диагностируйте по
`README.md` (раздел Troubleshooting) и логам (`host/proxy.log`, `journalctl -u sing-box`).

## Управление с Windows

После однократного `powershell -ExecutionPolicy Bypass -File host\install-command.ps1`
используй `omarchy-net status`, `omarchy-net on`, `omarchy-net off` и
`omarchy-net ru list|add|remove <домен...>`. `status` проверяет не только задачу и порты,
но и реальный IP через SOCKS. `off` останавливает только процессы сетапа и тем самым
включает kill switch в госте; HAPP и другие Windows-приложения не затрагиваются.
Изменение `ruDomains` через CLI запрашивает UAC и перезапускает прокси.

## Обновление и откат

- Изменение параметров: правка `settings.json` → повторный `host\install-host.ps1`;
  гостевые шаблоны зависят только от `socksPort` — при его смене повторить и `install-guest.sh`.
- Откат: `host\uninstall-host.ps1` (хост) и `guest/uninstall-guest.sh` (гость). Оба безопасны
  для пользовательских данных и не трогают HAPP.

## Ограничения

- Не запускайте инсталляторы одновременно с ранее настроенным отдельным `vds-proxy-tunnel.cmd`
  в автозапуске: два ssh будут конфликтовать за `tunnelPort`. Старый автозапуск туннеля удалить.
- Конфиг sing-box рассчитан на современный формат (1.12+). После мажорных обновлений sing-box
  в госте проверяйте `journalctl -u sing-box` на предмет переименованных полей.
